# 追加設定のインターフェース v1

個人用 dotfiles が追加設定の受け取り方を定義する。
会社ごとの dotfiles は対応する設定ファイルを提供する。
個人側は会社名や仕事用リポジトリの URL・ディレクトリ構成を知らなくてよい。

## 利用方法

```bash
# 個人設定だけ
bash /path/to/personal-dotfiles/install.sh

# 必要な設定だけ追加（片方だけでもよい）
bash /path/to/personal-dotfiles/install.sh \
  --extra-ssh-config /path/to/company-dotfiles/ssh/config \
  --extra-zsh-config /path/to/company-dotfiles/zsh/work.zsh

# 設定だけ配置する場合は --links-only を併用
```

設定ファイルは絶対パスでも呼び出し元からの相対パスでも指定できる。
同じ引数の複数指定はエラー。複数ファイルが必要なら、追加設定内で
`Include` / `source` を使ってまとめる。引数の不備やファイルの不存在は適用前に検出する。

## ファイルごとの契約

| 引数 | 提供する内容 | 配置先 |
| --- | --- | --- |
| `--extra-ssh-config FILE` | OpenSSH 形式の追加ホスト設定 | `~/.ssh/config.d/50-extra.conf` |
| `--extra-zsh-config FILE` | Zsh の追加設定・関数定義 | `~/.config/dotfiles/extra.zsh` |

どちらも元ファイルの絶対パスへのシンボリックリンクとして配置する。
仕事側に `install.sh` は不要。配置の責任は個人側のインストーラーが持つ。
ファイル名やリポジトリ内の配置は任意。追加ファイルには共通の `.zshrc` や
SSH config 自体を指定せず、追加設定のみを記述した独立したファイルを指定する。
設置後も元ファイルを削除・移動しない。移動したら新しいパスを指定して再実行する。

### Zsh

共通設定 → `~/.config/dotfiles/extra.zsh` → 任意の
`~/.config/dotfiles/local.zsh` の順に読み込む。
`local.zsh` は機器固有の設定用で、インストーラーは作成・変更しない。
追加設定が存在しない場合は読み込まない。

追加ファイルは設定と関数定義を中心にし、ログイン・デプロイ・秘密情報の取得を
起動時に実行しない。追加設定の変更は新しいシェルから有効になる。
既存シェルの環境変数や関数を消す処理は行わない。

### SSH

`~/.ssh/config.d/*.conf` → Colima → 共通設定の順に読み込む。
追加設定の変更は次の接続から有効になる。
`IdentityFile` は複数指定すると追加されるため、共通側は `github.com` の鍵を
固定しない。私用の鍵を明示する接続には `github-private` を使う。
会社側は必要に応じて `Host github.com` の鍵を指定できる。

## 再実行と切り替え

- 同じ元ファイルへのリンクがあれば何もしない。バックアップも増やさない。
- 異なる既存ファイル・ディレクトリ・リンクは `<配置先>.backup.XXXXXX/original` に退避する。
- 指定しなかった追加設定は維持する。個人用だけの再実行で仕事用設定は外れない。
- 別の会社用ファイルを指定すると、その種類の追加設定を切り替える。
- 個人側の管理ファイルを仕事用の内容で書き換えない。
- ツール導入は通常実行時に必要な状態へそろえる。`--links-only` では実行しない。

追加設定を外す場合は、配置したリンクだけを明示的に外す。元ファイルは残す。
機器移行では元ファイルも会社の保管先から復元し、再度指定する。

## 管理先の分担

| 管理先 | 内容 |
| --- | --- |
| 個人用 dotfiles | 私用設定、汎用ツール、会社を問わず使える関数、このインターフェース |
| 会社管理の仕事用 dotfiles | 社内接続先、会社固有のプロジェクト ID・関数・設定 |
| 別の秘密情報保管先 | 秘密鍵、API キー、トークン。どちらのリポジトリにもコミットしない |

`templates/work-dotfiles/` は会社情報を含まないファイルの原型。
会社管理の別の場所へコピーし、会社に合わせて編集する。
汎用の業務ツールも個人側に置く。会社固有の設定だけを仕事側に置く。

## 今回の移行用データ

`.local/` は Git 管理外の一時置き場。新しい Mac へ clone しても復元されない。
移行前にそれぞれの保管先を用意する。

- `.local/work-dotfiles/`: 社内接続先と会社固有の Gemini・PAM 設定を移した仕事用原稿。
  会社管理の場所へ移し、上記の引数で個人側の `install.sh` に渡す。
- `.local/before-split/`: 分離前の `.zshrc` と SSH 設定のローカルバックアップ。

`local.zsh` の情報も別途バックアップが必要。
